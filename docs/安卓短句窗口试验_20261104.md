# Android test2：短句计算窗口试验

test1的手机记录确认启用arm64-fp16-dotprod。四次识别62.623／63.064／64.650／68.279秒，编码61.357／60.966／63.795／67.510秒，模型加载均0。原录音2.584～9.448秒，耗时仍接近，主要瓶颈是完整音频编码窗口。

本次保留模型、Q5等级和全部输入样本，通过whisper.cpp v1.8.3公开audio_ctx参数减少短句的补零计算。先加2秒余量，再向上取128位置的倍数；最低512位置（10.24秒），达到模型上限或录音≥28秒时使用原完整窗口。没有对录音剪头、剪尾或删除中间停顿；长录音沿用原分段。默认正式接口仍使用完整窗口，只有明确传shortAudio且在Android时才调用新JNI入口。

**这是可关闭的试验，不能承诺所有录音准确度不变。** 256位置的早期试验使一条录音的rock识别错误，已拒绝该方案。512／640位置重新对照四条真实原录音，在本地CPU上与原完整窗口转写归一化一致（忽略大小写与标点）；这不是人工全文校对或大规模准确率验收。原始音频及转写只保留在本机私有测试目录，不混入APK、源码或公开补丁。

一条2.976秒录音的桌面CPU、16线程对照：完整窗口编码10759.05ms／总12043.13ms，512窗口编码2618.86ms／总3771.34ms。CUDA短窗口的首调用结果不可代表手机CPU速度，未据此声称手机秒数。手机test2仍待用户实测。

独立测试APK的entry开启试验，默认勾选“短句加速（试验）”；麦克风设置里可关闭，下一条恢复完整窗口，设置持久保存。每句下方显示识别、编码与实际计算窗口，导出保留audio_context、short_audio_requested和native_library；历史转写及成绩不改。test2沿用test1的包名和本地测试签名、增加版本code，可覆盖安装保留已导入模型／绑定／记录；不用卸载重装。正式原版保持独立，未修改正式Release。

验证包括原有28组Java回归、6组JS回归、C++6个边界及全部支持输入范围覆盖、真实口语页面／假麦克风／隔离桥接的短句开关与完整模式请求、设置刷新保留、390px布局、无脚本错误。Android原生库、全部生产Java和DEX重编，签名、原生符号、16KB ELF对齐、APK ZIP及覆盖文件核对另做；这些不代替手机速度或DeepSeek独立验收。
