# Windows每轮识别约20秒

这次优化针对原生识别推理，不是考官回复时间或前端轮询时间。保留上一轮无回复修复，界面沿用现有设计。

## 实测与范围

同一台i9-13900HX、RTX 5070 Ti Laptop电脑，同一份固定法语Q5模型，同一组16kHz合成法语录音。1.67秒短句原版冷态23.109秒、连续第二轮22.098秒；3.56秒句子22.867秒。

| 路径 | 1.67秒短句热态 | 3.56秒短句热态 |
| --- | ---: | ---: |
| 原版强制CPU、4线程 | 22.098秒 | 22.867秒 |
| OpenBLAS、16线程 | 11.815秒 | 12.280秒 |
| CUDA显卡 | 0.663秒 | 0.918秒 |

这些数字不包含考官回复，也不代表未知硬件或长录音的速度保证。两句识别结果与原版一致（数字可能显示为阿拉伯数字），不是总体识别准确率验收。

首次使用CUDA时可能有较长的驱动／内核准备：此次首次GPU冷调用为42.214秒。软件现在把模型加载和GPU预热放在录音前的“首次语音准备”阶段，显示进度；完成后才能开始。CPU只提前加载模型，不额外运行一轮无意义的CPU推理。不能把准备时间隐藏后宣称冷启动也只需一秒。

## 代码与运行库

- JNI不再强制关闭GPU。存在可用GPU后端时使用GPU；不可用时回CPU。`QIHANG_ASR_GPU=0`可用于测试强制CPU。
- Windows线程预算提升至最多16，保留至少一个逻辑CPU；移动端仍最多4。实际效果取决于CPU。
- Windows包带同版whisper.cpp/OpenBLAS插件；自动加速包额外带CUDA运行库，不要求用户安装开发工具或Python。不包含模型权重，继续使用原Q5文件。
- 准备状态独立于“模型已导入”，不会在首次准备期间开放录音。识别结果记录加载、推理、编码器、解码器耗时、线程数与实际CPU/GPU路径，供定位问题。
- 健康接口 `oralProtocol` 更新为 `20261102-asr-performance`，避免误用上一版后台。无需清空学习数据或绑定。

开发构建可通过 `QIHANG_NATIVE_TOOLS`、`QIHANG_MINGW_BIN`、`QIHANG_JDK_HOME`、`QIHANG_WHISPER_DLL`指定本机工具。`QIHANG_WHISPER_BIN`指向同一v1.8.3运行库目录，打包器会复制明确列出的可选BLAS/CUDA依赖；不能混用其他whisper版本。来源及许可见native/licenses/SOURCES.md。

## 复验

关闭旧版全部页面并等原后台退出，完整解压候选包，双击启动。原 `%LOCALAPPDATA%/QihangFrench` 中的模型、绑定、记录保持使用。首次准备后页面显示CPU或GPU；不知道显卡型号时可先使用自动加速包，不可用时用CPU兼容包。

先说短句，再说十秒左右的完整回答，检查用时、文字、考官回复和回听。结果仍慢时，提供页面显示的CPU/GPU及记录导出的recognition字段，区分硬件限制、加载和推理。

开发者可编译 `native/tests/AsrBench.java`，使用应用的JSON jar及原生库，传入模型路径、两个WAV、线程数和输出JSON。基准不读写正式学习记录，不把参考答案传给识别器。

## 最终原生RPC通道复验

同一生产Java/JNI主机、同一录音保存与识别API，模型准备完成后（各两条合成短句）：

- GPU：从提交识别到返回JSON约688ms／921ms；原生推理652ms／853ms；模型重载均0ms。
- 隐藏GPU模拟CPU回退：约11047ms／11109ms；推理约11018ms／11014ms；模型重载均0ms。
- GPU首次准备37619ms，CPU只加载准备1240ms。准备期间录音被明确拒绝，准备本身没有生成练习记录。

CPU回退测试在本机以CUDA_VISIBLE_DEVICES=-1执行，不冒充已在同伴未知硬件上测试。原始WAV字节核对不变，模型SHA-256核对不变；仅使用合成测试录音，未改正式数据。
