# Windows口语识别后无回复修复

适用基础版本：2.1.1-beta.1的原生口语链路，基于main `c8f79f13c8ad75891d65e15c8e6b62a2d221aa0d`。

## 原因和改动

客户端需要考官先调用 `self.french_exam.get_current_task`，才能播放符合本轮题卡的回答。原来的“陪练引导问答”等控制词可能直接触发普通问候，考官没有读取任务，返回的文字和音频因此被拦截。

原生后端改用简短的“读取当前任务”作为detect控制词，实际题卡、识别文字和对话仍通过MCP传递。每轮重新读取任务，陪练、模拟和评价共用此入口；不会把考生原句塞进detect。长提示会被托管平台拒绝，不能通过加长detect解决。

没有读取任务时，18秒内给出明确错误；读到任务后才进入90秒回复等待。平台发送空的tts stop时立即结束等待并保留原声和文字，不把空回复记为完成。

识别任务先立即查询一次，进行中才间隔120毫秒查询，去掉原先每次固定等待500毫秒。模型、量化精度及CPU推理参数保持不变；这减少结果取回延迟，不能保证所有电脑都在一秒内识别。

小智角色配置新增“读取当前任务”的说明，已有角色建议同步 `src/oral/examiner-config.js`。连接是否支持任务工具、是否配置法语音色仍需分别确认。

## 更新和复测

先结束当前练习并关闭旧版页面，等待其本机后台退出（当前版本空闲超时约3分钟），再完整解压候选Windows包并双击启动。更新使用原 `%LOCALAPPDATA%/QihangFrench` 数据目录，模型和绑定不用重新导入，不要删除该目录。

健康接口 `/__qihang_health` 的 `oralProtocol` 应是 `20261102-task-trigger`。修复版会拒绝复用缺少这个标识的旧后台，避免误把旧进程当成已更新。

依次测试：引导问答开场及两轮回应、信息交换由考生提问、情景购买、原声与考官回听、结束后的评价。额外测试断网、识别失败及“继续”恢复，确认文字和录音保留。模拟或协议替身通过不等于各目标设备的独立验收。
