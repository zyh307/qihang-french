# Android v2.2.4 每句识别慢：芯片指令加速候选

用户反馈 Redmi Note 14 Pro、v2.2.4，每句约100秒。此次在main ddfc8ec上单独修复，保留当前大型法语模型；不把参考计时或等待提示的调整当推理提速。

## 改动

旧安卓编译固定`-march=armv8-a`，未启用FP16算术和dotprod扩展。新构建输出基础、FP16、FP16+dotprod三套完整推理库，使用同一whisper.cpp v1.8.3和Opus 1.5.2源码。一个单独的基础ARM64探测库读取Linux HWCAP，在初始化推理JNI前选择受支持的最高实现。FP16同时要求scalar/vector能力；dotprod额外要求点积能力。未知设备、缺探测库或高阶库加载失败都安全回退，不在旧手机强行运行扩展指令。

这与上游[Android构建示例](https://github.com/ggml-org/whisper.cpp/blob/v1.8.3/examples/whisper.android/lib/src/main/jni/whisper/CMakeLists.txt)按ARM能力提供FP16实现的方向一致。没有缩短音频上下文、删除音频、提示答案或更换小模型。仍是手机离线计算，无法据此承诺100秒一定降至某个秒数。

打包要求同时携带4个so，缺失时明确构建失败；不允许默默交付仅含基础库的新APK。原生库通过本地NDK r27d编译，另附可由维护者添加的CI模板，固定依赖commit和NDK版本；当前GitHub登录缺少workflow权限，模板没有提交至PR，也没有远端CI成功结论。交付包含SHA256清单，复核ELF16KB页对齐、JNI探测符号及实际FP16/dotprod指令。原生库不含模型、账号、签名私钥、录音或历史。
